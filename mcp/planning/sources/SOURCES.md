# Исходные пакеты Planning MCP

Каталог содержит неизменённые снимки исходного кода, который нужен Planning
MCP. Файлы в этих каталогах не редактируются вручную; обновление выполняется
повторным копированием нужного коммита исходного репозитория.

| Снимок                                                          | Источник                | Коммит при подготовке                      |
|-----------------------------------------------------------------|-------------------------|--------------------------------------------|
| `stairs-resource-model/`                                        | `stairs-resource-model` | `c8f2373e17439ba7772d94f7a3e5bbe1a8c47729` |
| `stairs-storage/src/stairs_storage/`                            | `stairs_storage`        | `6ff9580d90e5b293aceb96904b17960b351adcb2` |
| `stairs-backend/services/scheduler/work_estimator/field_dev.py` | `stairs-backend`        | `fea2e0f054116fa411be8204fbd5ab94573ae149` |

`pyproject.toml`, тесты, `.env` и прочие файлы с настройками не копируются.
Зависимости исходных пакетов устанавливаются из MCP `requirements.txt`, а не
через приватные VCS-URL.

## Локальный патч: удаление секрета из снимка

`agent_wrapper.py` и `jobs.py` содержат единственное ручное отличие от
исходного кода: захардкоженный DSN с паролем заменён чтением `RM_ADAPTER_CONN_STR`
из окружения (`_storage()`). Причина — секрет не должен лежать в дереве.
При обновлении снимка сверить, что исходный проект тоже убрал секрет; иначе
повторить патч. Пароль остаётся в истории git — чистить историю отдельно.

## Формат моделей: JSON + legacy pickle

Runtime (`src/stairs_resource_model/res_time_model.py`) читает оба формата:
сначала декларативный JSON `planning-model/v1`, иначе legacy pickle
бэкенд-пайплайна (только доверенная admin-БД, десериализация pickle разрешена только в этом
модуле). Сами снимки выше — без изменений и соответствуют коммитам из таблицы.
